# 5C.1b review — general-path agent reliability

## What was wrong (measured live)

| Cause | Evidence | Fix |
| --- | --- | --- |
| Non-streaming completions over about 30 s fail at the HTTP gateway (502 "upstream request failed") | Reproduced directly: the same long request failed non-streaming at 30.3 s and **succeeded streamed in 40.9 s**. General-path turns with larger context routinely exceeded 30 s | All NVIDIA models stream (`apps/api/app/llm.py`); LangChain still assembles tool calls |
| The model sent `pmid: "None"` (rejected) and repeated identical searches, spending the four-search budget | Traced tool arguments in a live run | "None"/"null" treated as absent; identical searches return the earlier result without spending budget |
| Context grew without bound (each full-text page about 17 KB, preparation record about 12 KB) | The failing call carried 77 k characters | Search results shown to the model as titles, handles and short excerpts; the oldest bulky results are shortened once past a size budget, keeping every ID and locator; cited extractions are never shortened |
| Runs ended in errors: step limit (`GraphRecursionError`), deadline, a prose reply instead of a decision, an invalid "unsupported" claim | Live failures in each category | A wrap-up window (75 s before the deadline or after 20 tool calls) allows only extraction of retrieved sources, the structure check and the cited answer; any other ending concludes from what the tools recorded |
| Interrupted streams (`ChunkedEncodingError`) | One live primary failure after streaming was enabled | Model calls retry once on timeouts and transient transport errors; tools are never replayed |

No scientific gate changed. The audited comparison still requires a valid cited extraction, and a run with no simulation is reported as *needs inputs*, never filled in.

Before 5C.1b the general path failed **6 of 6** runs with provider errors. It now ends honestly **4 of 4**. Across all live runs of the main question since the 5C.1 extraction fix, **8 of 10** completed end to end, with the labeled saved demo as the fallback. Per-batch receipts are in [`5C.1b-reliability.json`](../../data/research/verification/5C.1b-reliability.json).

## Remaining limits

- General-path runs take about 160–185 s and often run out of time before the written answer validates. They report their extracted values and missing inputs, but they are not a smooth live demo. They show the agent's honesty, not a finished simulation.
- The main question's remaining failure mode is extraction quality: when every attempt on both papers is rejected, the run ends at *needs inputs* by design.
- Streaming makes slow calls succeed, so runs can now use the full 180 s budget.

## Plan assessment

**Keep the plan.** The demo keeps the main question plus the 95% follow-up, with the saved demo as the fallback. The general path is honest but slow; making it fast enough to demo live is out of scope for this hackathon.
