# Subphase 2A review — workspace controls and scenario state

## Delivered

- The user specified that another contributor is handling visual UI and aesthetics. This chunk therefore provides a **headless, typed integration layer** and avoids changing page layout or styling. `docs/FRONTEND_INTEGRATION.md` gives that contributor an explicit hook/API handoff.
- `POST /api/simulations/adjust` accepts one control change, resolves mathematical links on the server, and returns a complete new `SimulationResult` in one request. It supports alternative-scenario edits to volume, clearance, effective half-life, association, dissociation, KD, exposure factor, uniform infusion amount, and dosing interval; common duration and analytical occupancy threshold are global controls. The baseline scenario is protected from scenario-specific edits.
- An edited experiment is `mode=custom`, `support=conditional`. Its original evidence remains present. New values are timestamped `user_supplied` **candidate** records, not mislabeled reviewed measurements. Linked derived values are `calculated` candidate records with parent IDs and formulas. The schema allows these explicitly conditional user-driven values while still rejecting candidate source measurements or rejected/inapplicable evidence from runnable configurations.
- `apps/web/app/api/simulations` and `/adjust` provide same-origin proxy routes. `apps/web/lib/simulation-client.ts` provides typed requests and actionable 422/network errors. `apps/web/lib/workspace-state.ts` builds requests, checks numeric inputs, and excludes the baseline from editable alternatives. `apps/web/hooks/useExperimentWorkspace.ts` owns the current server-validated experiment/result, selected alternative, loading/error status, edit action, refresh, and reset-to-initial action. The hook calls no LLM.
- Generated OpenAPI, TypeScript, normalized example, and the checked-in 1C response fixture were refreshed because the normalized schema now includes optional dosing interval and user-entry metadata. The scientific numerical results of the unedited fixture remain the same; its configuration hash and result ID changed because the normalized configuration shape changed.

The `dose_mg` control sets every infusion in the selected alternative to the specified amount. The `dosing_interval_h` control creates a finite repeated schedule inside the horizon, using the first infusion for the initial dose and the second infusion (or first if absent) for later doses. These are **user-defined mathematical interventions**, not clinical dose recommendations. The hook currently refuses a second edit while one request is in flight; Phase 2C will improve rapid-edit behavior. No visual parameter panel or graphs are claimed in this chunk.
