### Fixes

1. **Validated extraction erased by a failed retry (live reliability defect).** The agent records one review per paper. A rejected re-extraction of a paper replaced an earlier validated extraction of the same paper, which closed the research gate. The reviewed demo question then ended at *needs inputs* despite valid cited values. A failed later attempt now keeps the validated outcome; both attempts remain in the execution ledger. Regression test `test_failed_retry_does_not_erase_a_validated_extraction_of_the_same_paper` fails without the fix. Live: 2 of 4 runs complete before (1 without its written answer), 3 of 3 after.
2. **Two pre-existing test failures.** Result IDs derive from configuration hashes. A result solved on one machine (the saved demo) was compared exactly with the same configuration solved here, and they differed in the last floating-point bit (max relative difference about 1e-8). The tests now compare floats to a relative 1e-6, with everything else still exact (`apps/api/tests/numeric.py`).
3. **Contradictory follow-up badge.** Edits are always verdict *undetermined* by design, so a decisive follow-up answer showed "Not determined" beside it. The badge now reads *Follow-up experiment result*; the stored verdict is unchanged.

### Unresolved

- **General (non-preset) agent path is not demo-ready live.** The agent repeats `search_hypothesis_evidence` with arguments the session-bound tool rejects, does not start a preparation on the baseline question, and the enlarged request then fails at NVIDIA (502, 3 of 3). One imatinib run hit the 52-step graph limit and raised instead of returning *needs inputs*. The other imatinib run ended correctly with *needs inputs*, the 1IEP structure and a cited answer.
- The primary answer's verdict varies between *mixed* and *undetermined* across runs; both are scientifically allowed for a censored comparison.
- Synthesis rejection remains possible (1 pre-fix run produced curves without a written answer).
- Live verification ran in a cloud container; the demonstration machine and network must be re-checked in 6B.

## Plan assessment

**Revision recommended — risk.** The product story ("the agent chooses the numbers that drive the graphs") is literally true only on the general path, which is unreliable live today. Smallest revision: add **5C.1b — general-path agent reliability (about 2 hours)** before 5C.2:

- Reject search calls that copy session-bound request fields with a precise correction message (as extraction already does), and stop issuing searches past the budget.
- On the step or tool budget, end the run with an honest *needs inputs* or *failed* state and its recorded events, never an uncaught graph error.
- Bound tool-result size returned to the model so requests cannot grow into gateway failures.
- Acceptance: 3 consecutive live runs each of the trastuzumab-baseline and imatinib questions end in *completed* or *needs inputs* with a cited answer; no 502 or recursion failure.

A related, bounded opportunity for 5C.3: when a live extracted value matches an audited input (as clearance and volume did in every run), mark it as **confirmed by this run's extraction** on the live workflow screen, rather than presenting the audited inputs as unrelated.
