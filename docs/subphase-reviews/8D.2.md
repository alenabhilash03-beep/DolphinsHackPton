# 8D.2 review — Investigation history and contextual follow-up

## Delivered

- **Immutable result tree.** Every stored result records its parent, how it was made and the turn that produced it. Direct control edits are linked to the result whose configuration they edited.
- **History and reopen APIs**, with bounded summaries and no time series.
- **Explicit branching.** A result still accepts one agent experiment by default; a `branch` request starts another line from an earlier result. Nothing stored changes.
- **Context for follow-ups.** A follow-up turn gets the original research question and at most six short earlier steps, and its answer addresses the original question with the new result.
- **Workspace history panel** with Reopen, a branch notice, readable step titles, and restoration of the displayed result and history after reload.
- **Answer accuracy.** The current result's threshold outcomes are stated to the model, and a false "both stay above" summary is refused.

## Verification

- **414 backend tests (6 new) and 64 frontend tests (4 new) pass.** TypeScript, contract check and production build pass. The one failing backend test is the same pre-existing saved-demo float mismatch.
- **Required path, backend:** research → direct edit → agent follow-up → reopen → continue, with the tree's parents, depth and summaries checked; context is two steps and under 12,000 characters with no time series.
- **Branch and concurrency rules:** a second experiment from the same result is refused without `branch` (409 through the API) and accepted with it; a wrong hash or revision is refused even with `branch`; the earlier result is byte-identical afterwards.
- **Persistence:** the history is identical after constructing a new service on the same database; a database from before this change is upgraded and readable.
- **Browser, synthetic backend:** research → slider edit → follow-up proposal → reopen step 1 → change in words → reopen step 1 again (branch notice shown) → follow-up as a new branch → reload (displayed result and five steps restored) → slider edit → reload (edited curves restored). No page errors, no overflow at 390 px.
- **Live Nemotron, traced:** research (79 s) then "Set the occupancy threshold to 95%" (22 s). The follow-up answered the original question with verdict "supported": the longer half-life scenario is still above 95% at the end of the window while the stronger-affinity scenario falls below it.

## Not verified

- Very long investigations in a browser.

## Observations

- Before the threshold-facts change, the same live follow-up said both scenarios stay above 95%, contradicting the solver. Earlier-step text had biased it. Bounded context helps answers but is a real source of error; the guard added is specific to that one claim.
- The reviewed research result has the same ID as the pre-stored saved demo, so the research turn is attached to that existing row. A second research run producing the same result keeps the first turn.
- Needs-input research that produced no result does not appear in the history.
- The "supported" verdict above holds at the 95% threshold chosen in the follow-up; the answer states that threshold.
