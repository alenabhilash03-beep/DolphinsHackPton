# Subphase 2B review — Plotly comparison and synchronized timeline

## Delivered

- `apps/web/lib/plot-spec.ts` builds Plotly concentration and occupancy comparisons from one validated `SimulationResult`. Both charts use the same backend `time_h` array, converted from hours to days for display. Central concentration is labeled nM; occupancy fractions are converted to labeled percent. Scenario colors and labels remain consistent between graphs. Optional target-site concentration is explicitly labeled **prescribed site**, not measured free tissue exposure.
- Dose starts are marker traces, infusion/event boundaries are vertical guides, the selected analytical occupancy threshold is a horizontal guide, and a shared cursor line is placed at the timeline time. Concentration traces split at hypothetical bolus times so no sloped line is drawn across an instantaneous PK jump. Occupancy stays continuous.
- `apps/web/lib/timeline.ts` selects the nearest returned sample and reads concentration/occupancy values directly from the aligned arrays. `apps/web/hooks/useSimulationTimeline.ts` provides play, pause, seeking, cursor time, progress, and per-scenario readouts. Playback traverses physical simulation time; scrubbing snaps to a returned sample so displayed numbers exactly match the plotted source arrays. A result update preserves the last displayed time as closely as the new grid allows and pauses playback.
- `ScientificPlot` lazily mounts the Plotly React component in the browser. `TimelineControls` supplies minimal accessible play/pause and physical-time scrubbing controls that the UI contributor can restyle or replace. A separate `/preview/plots` route mounts both real charts and a current-time readout without changing the main page design. `docs/FRONTEND_INTEGRATION.md` now includes the 2B composition pattern.
- Plotly.js, its React wrapper, and TypeScript types are pinned in the npm lockfile. No LLM calls or molecular geometry changes are involved in timeline or chart updates.
