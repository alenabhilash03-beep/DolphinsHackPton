# Subphase 1C review — simulation API and reproducibility

## Delivered

- `POST /api/simulations` accepts a validated `SimulationRequest` and returns three aligned concentration/occupancy series, dense-solution metrics, the complete normalized experiment, model and solver versions, warnings, and diagnostics. It calls the deterministic Python engine directly and requires no AI provider or LangSmith credentials.
- `apps/api/app/simulation/registry.py` registers exactly one model, `one_compartment_effective_binding_v1`. The request is constrained to a one-year horizon, at most 64 administration events per scenario, 100–5000 requested output points, and an eight-second cooperative computation budget. The reviewed preset rejects hypothetical bolus input; custom mode must explicitly select it. These are computational guardrails, not claims about clinical applicability.
- `apps/api/app/simulation/service.py` builds one shared timeline with the exact dose boundaries, threshold crossings, early-time samples, and local samples after boundaries. A hypothetical bolus gets a pre-event point when it occurs inside the window. The final timeline stays at or under 5000 points. Scenario arrays and diagnostics share this timeline.
- The configuration hash is SHA-256 over canonical JSON of the normalized `ExperimentConfig`. The result ID hashes that configuration hash together with requested plot density and model/solver versions. Client revision is echoed to support stale-response handling, but it does not alter scientific results or result identity. Solver settings, knot count, boundaries, and actual output-point count are returned in `SimulationDiagnostics`.
- The solver checks a monotonic deadline between intervals and periodically in its right-hand side. Invalid scientific requests and exceeded limits return HTTP 422 with a reason. There is no background queue or hard process isolation in this MVP; the eight-second guard is cooperative.
- `data/examples/simulation-result.reference.json` is a checked-in complete response from the 0B reviewed fixture at 100 requested uniform points. `README.md` links the roadmap, API reference, and response fixture. The existing frontend preview now reports that the numerical API is ready without pretending to show plots.

The output remains a **conditional exploratory model**, not a validated clinical forecast or measured tumor occupancy. The 90% occupancy threshold is an analytical choice. A status of `still_above_at_horizon` is censored; it does not establish which intervention has longer ultimate retention.

The 100-point request returns 134 points because mandatory boundaries, threshold crossings, and early samples are added. `output_points` is a requested uniform-grid target, not an exact total. The returned count is explicit in diagnostics and remains capped at 5000. The checked-in response is an example under locked dependencies; scientific comparisons use tolerances rather than requiring bitwise equality across platforms.
